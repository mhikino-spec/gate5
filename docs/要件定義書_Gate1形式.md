# PC貸出機能 要件定義書

Gate1形式準拠版　版0.9.1　レビュー用草案

Gate1配布資料の第2章を構成と記載粒度の基準として、Gate5のPC貸出仕様とヒアリングを再構成した。実装担当者と業務担当者が、入力・状態・画面・処理結果を同じ基準で確認するための文書である。

Gate1の問い合わせ管理に固有のテーブル、ADMIN／MEMBER権限、NEW／DONE等の状態は、PC貸出の業務には転用しない。資料の文章を独立した操作命令とは扱わず、今回のユーザー依頼に基づき提出要件として参照する。提出実装のADMIN／MEMBERは、返却権限を具体化するために追加したデモ用の区分である。

## 2 要件定義書

### 2.1 概要

|項目|内容|
|---|---|
|機能名|共用ノートPCの貸出・返却および予約管理|
|対象ユーザー|社内の借用者本人、代理貸出の操作者。運用確認は情報システム部を想定|
|目的|PCの貸出状況を可視化し、二重貸出、貸出制限違反、返却時の不整合を防ぐ|
|対象規模|ヒアリング時点で約20台、全台貸出可能。20台をシステム上限にはしない|
|今回定義する範囲|状態表示、申請・確認・確定、返却、入力検証、排他制御、予約方針、延滞通知|
|別途確定する範囲|未来予約の確保・取消・変更、代理権限、メール配信条件、運用目標|
|対象外の管理機能|PC購入、修理・廃棄の管理画面、TABLET・MONITORへの貸出拡張|

### 2.2 用語定義

|用語|定義|
|---|---|
|端末|devicesの1レコードで識別する物理PC。機種名が同じでも別個体|
|借用者|PCを借りる社員。lendings.user_idで記録する対象|
|操作者|実際に画面を操作した人。代理操作時は借用者と異なる|
|貸出|実際にPCの利用を開始し、lendingsを作成して端末をLENTにする処理|
|予約|将来または当日の利用予定を確保する処理。実貸出と分離する補完案|
|未返却|lendings.returned_atがNULLである貸出|
|延滞|未返却かつ業務日がdue_dateを超えた状態とする案。端末状態コードは追加しない|
|業務日D|サーバー側の基準タイムゾーンによる当日。日本時間を使用する案|
|要求識別子|同一操作の再送を見分けるためのサーバー発行値。貸出・返却の重複登録防止に使用|
|競合|複数要求が同じ端末、または同じ借用者の上限を同時に確保しようとすること|

#### 追加データの定義案

未来予約は既存3テーブルだけでは予定期間を管理できない。reservationsを別管理する案を下表に示す。この表全体はQ-01の判断前の補完案であり、既存DBに存在するとは扱わない。

|カラム名|型|NULL|デフォルト|説明|
|---|---|---|---|---|
|id|BIGINT|NO|AUTO|予約主キー|
|device_id|BIGINT|NO|なし|予約する個体PC|
|user_id|BIGINT|NO|なし|予約の借用者|
|start_date|DATE|NO|なし|利用開始予定日|
|due_date|DATE|NO|なし|返却予定日|
|purpose|VARCHAR(100)|NO|なし|予約時の利用目的|
|status|VARCHAR(20)|NO|RESERVED|RESERVED／FULFILLED／CANCELLEDを候補とする|
|lending_id|BIGINT|YES|NULL|実貸出後のlendings.id。1予約を二重に実貸出しない|
|created_at|DATETIME|NO|現在日時|予約作成日時|
|updated_at|DATETIME|NO|現在日時|予約更新日時|

予約の状態遷移はRESERVED→FULFILLED（実貸出成功）、RESERVED→CANCELLED（取消）のみを基本案とする。取消権限・取消期限・変更・未受取の扱いはQ-01で確定する。予約成立だけではdevices.statusやlent_atを変更しない。

操作監査には操作者ID・借用者ID・対象ID・操作日時・結果・要求識別子を保存する案とする。要求識別子と確定結果の対応を保持し、同じ要求に同じ結果を返す。保存先・型・保管期間はQ-08で決める。メール宛先は既存列にないため、社員ディレクトリ等の取得元をQ-04で確定する。通知対象貸出ID・送信結果・再試行情報も保持する案とする。

参照整合を守り、履歴のある社員・端末の削除で貸出履歴を連鎖削除しない案とする。同一端末の未返却貸出を最大1件、同一借用者の未返却貸出を最大1件に制限する。制約・排他の方式はN-02に従う。

### 2.4 ステータスの定義と遷移

|コード|表示名|意味|
|---|---|---|
|AVAILABLE|貸出可能|現在、貸出可能な端末|
|LENT|利用中|未返却の貸出がある端末|
|REPAIR|利用停止|修理中で貸出できない端末|
|DISPOSED|利用停止|廃棄済みで貸出できない端末|

本機能の操作で許可する変更だけを○とする。×は本機能から変更不可、－は状態の維持で新規貸出を意味しない。修理・廃棄・復旧は別の管理機能のため、ここでは遷移を許可しない。

|変更前／変更後|AVAILABLE|LENT|REPAIR|DISPOSED|
|---|---|---|---|---|
|AVAILABLE|－|○ 貸出成功|×|×|
|LENT|○ 返却成功|－|×|×|
|REPAIR|×|×|－|×|
|DISPOSED|×|×|×|－|

!STATE!

返却時に貸出情報と端末状態が一致しない場合、AVAILABLEに上書きせずE-20で中止する。延滞しても端末コードはLENTのままとする。未来予約の予約状態と端末の現在状態は分ける。貸出中端末への修理・廃棄の管理側制御はQ-09で確定する。

### 2.5 ステータス変更に伴う付随処理

|処理または遷移|付随処理|
|---|---|
|AVAILABLE→LENT|最新の状態・借用者条件・入力値を再検証。lendingsを1件登録しlent_at=現在日時、returned_at=NULLとする。devices.status=LENTに更新|
|LENT→AVAILABLE|対象貸出IDの未返却を確認。returned_at=現在日時、devices.status=AVAILABLEを一括更新|
|全ての確定処理|要求識別子と結果を対応付ける案。成功後のみ完了表示。途中失敗は全体を取り消す|
|同一要求の再送|確定済み結果を返し、貸出・返却・監査を二重に記録しない案|
|予約成立|予約のみ作成し、devices.statusとlendingsは更新しない案|
|予約から実貸出|条件を再検証し、通常貸出登録と予約のFULFILLED化・lending_id設定を一括処理する案|
|返却期限超過|未返却を再確認して延滞通知の対象にする。メール失敗で貸出・返却を巻き戻さない案|

### 2.6 貸出と返却の業務ルール

|ID|業務ルール|根拠・確度・優先度|
|---|---|---|
|R-01|貸出対象はLAPTOPのみ。端末個体ごとに貸出を管理する|P1／個体指定は補完案 中|
|R-02|貸出確定時にAVAILABLEであることを再確認する。LENT・REPAIR・DISPOSED・不存在は拒否|H1・H3 方針／再確認は補完案 高|
|R-03|借用者は社員マスタに存在しACTIVEであること。LEAVE・RETIREDは貸出しない|H2 方針／未登録拒否は補完案 中|
|R-04|借用者1人あたり貸出上限1台。未返却貸出を数える案。代理操作でも借用者の件数で判定|H2 方針／数え方は補完案 高|
|R-05|代理貸出を許容する。代理権限と借用者を分けて検証する|H2 方針／権限・監査は補完案 中|
|R-06|同一端末への競合は1件だけ成立させる。先着判定はDB上で先に確保し正常確定できた要求を優先する案|H4 方針／判定点はQ-07 高|
|R-07|同じ要求の連打・再送・ブラウザバックは同じ処理結果を返し、新規登録しない|H8 課題／補完案 高|
|R-08|貸出登録と端末LENTへの変更、返却日時登録と端末AVAILABLEへの変更は、それぞれ1トランザクション|P1の処理を補完 高|
|R-09|当日予約を許容し、最長1か月先の予約を受け付ける|H5 方針／境界はQ-02 中|
|R-10|貸出期間は最長1週間。返却期限の起算と締め時刻は統一する|H6 方針／境界はQ-03 中|
|R-11|延滞中は新規貸出しない。返却操作は延滞を理由に禁止しない|H7 方針／返却許可は補完案 中|
|R-12|延滞者へ自動メールを送る。送信失敗で貸出・返却結果を巻き戻さない案|H7 方針／失敗分離は補完案 中|
|R-13|返却済み貸出を再返却して日時や別の貸出を変更しない。貸出IDで対象を特定|P1を補完 高|
|R-14|画面表示・ボタン押下時だけでなく、確定時の最新状態と業務日で許否を決める|補完案 高|
|R-15|不正遷移・権限不足・データ不整合では更新しない。通信断は成功・失敗を断定せず結果照会する|H8／補完案 高|

貸出期間と予約可能期間を区別する。補完案では予約開始日は申込日から暦で1か月後まで、返却予定日は利用開始日から7日後までとする。月末・当日返却・締め時刻はQ-02・Q-03の確認対象である。Gate5資料内の「90日以内」「休業日は不可」は記入例のため採用しない。

代理貸出の上限・延滞・在籍状態は操作者ではなく借用者で判定する。許可される代理範囲はQ-05で決める。退職・休職・延滞によって新規貸出を制限しても、既存貸出の返却を妨げない運用を提案する。

### 2.7 画面仕様

画面名はGate5既存仕様に合わせ「貸出申請」「確認」「貸出完了」「返却」「返却完了」とする。未来予約は貸出と異なるため「予約申請」「予約確認」「予約完了」を別処理として示す案である。以下の配置・ボタン名・入力保持・並び順は、ヒアリングで決まった表示を除き補完案とする。

#### 貸出申請画面のレイアウト

!SCREEN!

画面内の資産番号、氏名、日付は表示例であり固定値ではない。端末の利用可否を先に確認し、その後に借用者・返却予定日・目的を入力する構成とする。

|画面|表示内容|操作と遷移|
|---|---|---|
|貸出申請|利用可否、端末プルダウン、借用者ID、借用者名、返却予定日、目的|「貸出する」で検証し確認へ。0件・入力不正は遷移しない|
|確認|端末資産番号・機種、借用者ID・氏名、返却予定日、目的を読取専用表示|「戻る」で申請へ値を保持。「確定」で最新条件を検証して貸出処理|
|貸出完了|S-01と実際の貸出結果|再読み込み・戻る再確定で重複登録しない|
|返却|未返却の貸出、端末、借用者、返却予定日、延滞の有無|対象貸出を選んで「返却する」。成功後に返却完了へ|
|返却完了|S-02と返却した端末|再送時は同じ返却結果を表示する|
|予約申請・確認・完了|借用者、開始日、返却予定日、期間別の空き、目的|開始日を先に指定して空き確認。予約完了S-03。実貸出と混同しない案|

#### 補完後の貸出フロー

!FLOW!

返却は「対象貸出選択→権限・未返却・端末整合性確認→returned_atと端末状態を同時更新→返却完了」とする。同一要求の再送は既存結果、不正な別要求はE-14またはE-18、不整合はE-20。更新失敗は全体を取り消す。

### 2.8 処理結果メッセージ

確定版では文言と句読点を統一する。{資産番号}等は実データに置き換え、日付はYYYY/MM/DDとする。H1・H4の短い状態表示・在庫文言以外は補完案。以下で前版のE番号を維持し、成功メッセージにS番号を追加した。

|ID|状況|メッセージ文言|表示種別|
|---|---|---|---|
