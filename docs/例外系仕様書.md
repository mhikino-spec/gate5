# 例外系仕様書 — 提出実装版

版：1.0 / 2026-09-12 / Python＋SQLite。Gate1形式の要件定義書を基準に、Gate5採点対象の実装仕様を固定した文書です。要求と実装の違いは洗い出し表で追跡します。

## 0 適用範囲と仕様の出所

Gate5配布資料のdevices・lendings・employees、貸出／返却の正常フローを実装する。聞き取りの「ノートPC」「1人1台」「休職・退職者は不可」「代理貸出可」「最長1週間」「延滞者の新規貸出禁止」を反映する。

次は実装のための補完案であり、業務承認を得た値ではない：返却日はJSTの当日D〜D+7（両端含む）、休日制限なし、確認トークン30分、ログイン30分、全ACTIVE操作者の代理貸出許可、返却は借用者本人または管理者、同時申請はDB書込権を取得して正常確定した側を優先する。厳密なクリック順は保証しない。

将来の貸出開始日を指定する予約とメール通知は未実装。配布資料中のバリデーション記入例を実際の業務規則とは混同しない。

## 1 バリデーション一覧

貸出は「貸出する」で確認情報を作る前と「確定」の直前に検証する。確定済み同一トークンは条件を再適用せず、保存済み結果を返す。エラーはページ上部の赤い枠にE番号と文言を表示し、原則として入力を保持する。元の要件案の項目直下表示から、提出実装では上部集約に変更した。

|ID|項目／条件|判定・正規化|検知時点|エラー／復帰|
|---|---|---|---|---|
|V-01|端末・社員・貸出ID|ASCII数字、1〜9223372036854775807、19桁以内。SQLはパラメータ化|確認・確定|E-09、修正|
|V-02|端末存在・種別|存在しLAPTOPである|確認・確定|E-01／E-05、選び直し|
|V-03|端末状態|AVAILABLEのみ。未返却貸出が残る不整合も拒否|表示・確認・確定|E-02／E-03／E-04／E-20|
|V-04|社員|存在しACTIVEである|確認・確定|E-06／E-07|
|V-05|借用者の未返却|0件。延滞判定を上限判定より先に行う|確認・確定|E-13／E-08、先に返却|
|V-06|日付形式|前後空白除去後にYYYY-MM-DDの実在日。自動補正しない|確認・確定|E-10|

ブラウザのrequiredは補助であり、サーバー側検証を必須とする。複数不備は処理順の最初の1件を表示する。貸出の順序はID→日付→目的→操作者→端末→借用者→延滞→上限。確定時は操作者・トークンを先に確認する。

## 2 業務ルール

|ID|ルール|実装箇所|
|---|---|---|
|R-01|貸出対象はLAPTOPかつAVAILABLE。画面でも利用中・利用停止は選択不可|loan_check / loan_page|
|R-02|借用者は存在するACTIVE社員。退職・休職者へ貸出しない|loan_check|
|R-03|未返却は借用者1人につき1件まで。貸出先は操作主体と別に記録|one_user_open / loan_check / requests.actor_id|
|R-04|目的は1〜100文字、返却予定日はD〜D+7|loan_payload|
|R-05|全ACTIVE社員の代理貸出をデモで許可。返却は本人またはADMIN|actor_check / return_check|
|R-06|同じ端末・同じ借用者への競合はBEGIN IMMEDIATEで直列化し、再検証する|execute / 部分一意インデックス2本|
|R-07|同一トークンの連打・再送は同じ結果。同じ内容でも新トークンなら新規申請として制限を再検証|requests.result / execute|
|R-08|貸出INSERT＋端末LENT＋監査INSERT＋要求結果保存は1トランザクション。返却も同様|execute|
|R-09|成功はCOMMIT後にのみ表示。失敗はROLLBACK、DBエラーE-15|execute / result_page|
|R-10|延滞は未返却かつdue_date<JST当日。新規貸出を拒否し、返却は許可|loan_check / returns_page|
|R-11|貸出ID単位で返却する。古い貸出の要求が新たな貸出に作用しない|return_check|
|R-12|貸出中の修理・廃棄などへの状態変更をDBで拒否|protect_lent_device|
|R-13|GETは貸出・返却を更新しない。確認済み内容はクライアント入力から復元しない|do_GET / do_POST / requests.payload|
|R-14|貸出・返却結果をSQLiteに永続化。同じ利用者が元の結果URLで照会可能|intent / result_page|

このR番号は本提出実装版の番号。参考要件定義書のR番号とは別管理とする。対応はX番号で追跡する。

### データ定義・整合性

配布3テーブルをSQLiteで表現する。BIGINTはINTEGER、VARCHARはTEXT、DATEはISO日付TEXT、DATETIMEはJSTオフセット付きISO文字列。returned_atとpurchased_atはNULL可。他の業務列はNOT NULL。元の桁数は目的とIDを除き管理入力画面がないため、マスター登録時の上限検証は今回対象外。

|テーブル|主な項目・補完|制約／用途|
|---|---|---|
|devices|id PK、asset_no UNIQUE、model_name、device_type、status、purchased_at|type・status CHECK、貸出中状態変更トリガー|
|employees|id PK、name、department、employment_status、role、salt、password_hash|ACTIVE／LEAVE／RETIRED、MEMBER／ADMIN CHECK。平文パスワード保存なし|
|lendings|id PK、device_id FK、user_id FK、lent_at、due_date、returned_at、purpose|未返却のdevice_id／user_idを各UNIQUE。purpose長1〜100|
|requests|token PK、actor_id FK、action、payload、created_at、result NULL可|確認済み内容と確定結果。result NULLは未完了|
|audit_log|id PK、token UNIQUE FK、actor_id FK、action、lending_id FK、occurred_at|確定操作のみを同一トランザクションで記録|

SQLite外部キー有効、WAL、書込待ち最大10秒。トランザクション範囲は、書込ロック取得→最新状態・社員再読込→制約検証→貸出／返却更新→端末更新→監査→結果保存→COMMIT。確認トークン作成のトランザクションとは別。確認中に端末を予約確保しない。

## 4 状態遷移表

|変更前|操作／条件|変更後|貸出データへの作用|不成立時|
|---|---|---|---|---|
|AVAILABLE|有効な貸出確定|LENT|未返却貸出を1件INSERT|入力・社員条件エラー、更新なし|
|LENT|未返却貸出の正当な返却|AVAILABLE|その貸出のreturned_atを設定|E-14／E-18／E-20、更新なし|
|LENT|別の貸出|LENT|追加なし|E-02、残数0ならE-04|
|REPAIR|貸出|REPAIR|追加なし|E-03|
|DISPOSED|貸出|DISPOSED|追加なし|E-03|
|AVAILABLE|返却|AVAILABLE|変更なし|対象なしE-14、不整合E-20|
|LENT＋未返却あり|修理・廃棄などへの直接変更|LENT|変更なし|DBトリガーで拒否。管理画面は対象外|
|任意|トランザクション失敗|処理前の状態|すべてロールバック|E-15|
|完了済要求|同じ確定を再送|変化なし|追加・上書きなし|保存した完了結果|
|未完了要求|確認から30分超|変化なし|変更なし|E-17|

同じ確定要求の再送結果は、後から返却された場合も「その要求が成功した履歴」を返す。現在の在庫状態は申請・返却一覧で確認する。

## 5 検証と残る制約

自動テストはtests/test_app.py（業務・DB）とtests/test_http.py（HTTP認証、CSRF、確認改ざん、HTML表示、再送）。結果はevidence/test_results.txt。モックは合成ではなく実アプリのスクリーンショット。再現方法はモック画像一覧を参照する。

通信断そのものやOSの強制終了・実メール配信は試験していない。同じ要求を再送したときの再登録防止とSQLite再接続後の結果取得を試験した。セッションはプロセス内メモリのため再起動後は再ログインが必要。自動結果照会、SSO、ログイン試行制限、バックアップ運用、TLS、ログ保持期間、負荷目標は今回未実装／未確定。localhost専用の課題実装であり、そのまま本番公開する構成ではない。
