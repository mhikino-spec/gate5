# Gate5 共用PC貸出・返却 — 提出物

Gate5配布仕様＋聞き取りTXTを統合し、Python＋SQLiteのローカル実装、例外系仕様、モック、検証結果を同梱する。

## 1 起動方法

Python 3.10以上。外部パッケージ不要。ZIPを展開し、このREADMEとapp.pyがあるフォルダーで実行する。

```powershell
python app.py --seed
```

ブラウザで http://127.0.0.1:8765/ を開く。終了は起動したターミナルでCtrl+C。

- 初回はdata/gate5.sqlite3を自動作成する。--seedは空の社員テーブルにだけ架空データを作り、既存データをリセットしない。
- 既存データを残して初期状態を試す場合は、未使用のファイル名で `python app.py --seed --db data/another-demo.sqlite3 --port 8766` と起動する。
- 1001 / demo1234：管理者。1002〜1005 / demo1234：一般社員。すべて架空アカウント。
- 1006は休職、1007は退職のためログイン／貸出対象外。1008は延滞データがある。
- ノートPC20台＋対象外種別の検証用タブレット1台。初期状態はPC-0002が貸出中、PC-0003が修理、PC-0004が廃棄、残り17台が貸出可能。

起動時のデータはヒアリングの「全台空き」を忠実に再現するものではなく、例外を評価するためのテスト用状態である。インターネット公開はせず、127.0.0.1のみに待受する。

## 5 振り返り

以下は成果物と検証結果に基づく振り返り案。本人の経験やGate1時点の記録を創作したものではない。提出前に本人の言葉で確認・補記する。

### 5-1 0件だった観点

最終版は8観点すべて1件以上で、0件の観点はない。入力値7件に対し他カテゴリも4〜5件あり、入力チェックだけに偏らないようにした。通知の失敗など、仕様を決めても今回実装できない項目も削らず残した。

### 5-2 正常フローだけでは漏れやすい3点と理由

|見落としやすい点|理由と今回の対応|
|---|---|
|同じ社員が別のPCを同時に借りる|端末単位の二重貸出だけを考えると1人1台を守れない。借用者にも部分一意制約を設け、同時確定テストを追加した|
|古い返却要求が再貸出後に届く|端末IDだけで返却すると、新しい借用者の貸出を終了させ得る。貸出IDと未返却条件で絞り、古い要求のテストを追加した|
|DB確定後の応答が届かない|画面に成功が見えなくてもDBは確定済みの場合がある。同じ要求トークンに結果を保存し、再送で追加登録しない方式を採った。自動照会UIは残課題|

これらは今回の検討対象から選んだ学習ポイントであり、「本人が最初に見落とした」という履歴は確認できていない。
